# 陶芸記録(とうげいきろく)

作陶(成形・素焼き・装飾・本焼き)の記録と、アイディア帳を管理する個人用Webアプリです。

**このアプリの最大の特徴:入力したデータは、あなたが今使っているブラウザの中だけに保存されます。**
サーバーには一切送信されません(フォントの読み込みだけ、Googleのサーバーへ通信します。個人データは含まれません)。

---

## 1. これは何のアプリ?

- 作品ごとに「成形→素焼き→装飾→本焼き」の記録(日付・土・サイズ・釉薬・技法・写真など)をつける
- 気になった作品や技法を「アイディア帳」に画像・URL・メモで残す
- データはブラウザ内(IndexedDB)に保存。他人や開発者(Anthropic含む)には一切送信されません
- バックアップ書き出し(JSONファイル)・復元に対応。機種変更やブラウザの引っ越しはこれで行います

## 2. データはどこに保存される?

「ブラウザの中」に保存されます。具体的には **IndexedDB** という、ブラウザに内蔵されたデータ保存の仕組みです。

- ✅ サーバーに送信されない、ネット接続がなくても使える
- ⚠️ その代わり、**保存場所は「その端末の、そのブラウザ」だけ**です
  - iPhoneのSafariで入力したデータは、同じiPhoneのChromeでは見えません
  - ブラウザの「閲覧履歴・データを削除」をすると、記録も一緒に消えます
  - シークレット/プライベートブラウジングでは、タブを閉じると保存されないことがあります

→ だからこそ「バックアップ」がとても重要です(次項)。

## 3. バックアップ・復元の使い方

アプリの「制作記録」タブの一番下に、2つのボタンがあります。

- **「バックアップを書き出す」**:今の全データ(作品・アイディア・技法一覧)を1つのJSONファイルとしてダウンロードします。ファイル名は `陶芸記録_backup_YYYY-MM-DD.json` です。
- **「復元する」**:バックアップJSONファイルを選ぶと、内容を確認したうえで、現在のデータをそのファイルの内容で置き換えます(実行前に確認画面が出ます)。

**運用のおすすめ**:月1回など決めたタイミングでバックアップを書き出し、Googleドライブやパソコンなど、ブラウザ以外の場所に保管してください。機種変更・ブラウザ変更のときは、新しい端末でこのアプリを開き、「復元する」でそのファイルを読み込めば、記録を引き継げます。

バックアップファイルには `schemaVersion`(データ形式のバージョン番号)が入っています。将来アプリの機能が増えてデータの形が変わっても、古いバックアップを読み込めるように設計してあります。壊れたファイルや対応外の形式を読み込んだ場合は、エラーメッセージが出るだけで、今のデータが壊れることはありません。

## 4. 技術構成

- React + TypeScript + Vite(最小限の依存ライブラリのみ)
- データ保存はアダプター構成(`src/storage/StorageAdapter.ts` というインターフェースの背後に実装を隠しています)。今はIndexedDBですが、将来Firebase/Supabaseなどでクラウド同期を追加したくなったら、この1ファイルを差し替えるだけで済むようにしてあります
- 外部通信は「Googleフォントの読み込み」のみ(表示用の書体データだけで、個人情報は含まれません)。オフラインでもフォントが読み込めないだけで、アプリ自体は使えます

## 5. 手元で動かす(開発者向け操作)

パソコンに [Node.js](https://nodejs.org/ja/)(18以上)がインストールされている前提です。

```bash
npm install       # 必要なライブラリを取得
npm run dev       # 開発サーバー起動(表示されたURLをブラウザで開く)
npm run build     # 本番用ビルド(distフォルダが生成される)
npm run preview   # ビルド結果をローカルで確認
```

## 6. GitHubへの公開手順(プログラミング未経験の方向け)

Gitコマンドを使わず、ブラウザの操作だけで公開する方法です。

### ステップ1:GitHubアカウントを作る

1. [https://github.com](https://github.com) を開く
2. 右上の「Sign up」をクリック
3. メールアドレス・パスワードなどを入力してアカウントを作成(無料)

### ステップ2:新しいリポジトリ(保管庫)を作る

1. 右上の「+」→「New repository」をクリック
2. Repository name に `tougei-kiroku` などの名前を入力
3. 「Public」を選択(無料公開に必要)
4. 「Create repository」をクリック

### ステップ3:ファイルをアップロードする

1. 作成されたリポジトリのページで「uploading an existing file」というリンクをクリック
   (見当たらない場合は「Add file」→「Upload files」)
2. このアプリのフォルダの中身(`src`フォルダ、`package.json`、`index.html` など、**フォルダの中身をまとめて**)を、アップロード画面にドラッグ&ドロップ
3. 下の方にある「Commit changes」をクリック

これでGitHubへの公開は完了です。リポジトリのURL(例: `https://github.com/あなたの名前/tougei-kiroku`)が、次のVercelでの公開に必要になります。

---

## 7. 無料ホスティングへの公開手順(Vercel)

2026年時点で、個人の小規模なReactアプリを完全無料・カード登録不要で公開できる選択肢として **Vercel** をおすすめします(Netlify・Cloudflare Pagesも同様に無料枠がありますが、Viteプロジェクトの自動認識のしやすさからVercelを第一候補とします)。

### ステップ1:Vercelアカウントを作る

1. [https://vercel.com](https://vercel.com) を開く
2. 「Sign Up」をクリックし、「Continue with GitHub」を選択
3. 先ほど作ったGitHubアカウントでログイン(連携)する

### ステップ2:プロジェクトをインポートする

1. Vercelのダッシュボードで「Add New...」→「Project」をクリック
2. 先ほど作った `tougei-kiroku` リポジトリを探して「Import」をクリック
3. Framework Preset が自動的に「Vite」と認識されます(されない場合は手動で選択)
4. そのまま「Deploy」をクリック

数十秒〜数分待つと、公開用のURL(例: `https://tougei-kiroku.vercel.app`)が発行されます。これが友人にそのまま送れる公開URLです。

## 8. 必要なアカウント

- **GitHub**(無料):コードの保管・公開用
- **Vercel**(無料):Webサイトとして公開するため。GitHubアカウントでログインできます

クレジットカードの登録は、この用途(個人の趣味アプリを無料枠で公開)では不要です。

## 9. 費用について

- 個人が趣味で使う範囲(閲覧数・データ量)であれば、GitHub・Vercelともに無料枠内で収まります
- 費用が発生しうるのは、将来「独自ドメインの購入」「アクセスが非常に多いサービスへ育てる」「Firebase等の有料クラウドDBを追加する」場合です。今回の構成(ブラウザ内保存+静的サイト公開)ではその心配はありません

## 10. 友人に使ってもらう方法

Vercelで発行されたURLを送るだけで、相手はインストール不要でそのままブラウザで使えます。ただし、**データは相手の端末に保存される**ため、あなたと相手でデータが共有されることはありません(それぞれ別々の記録になります)。これはこのアプリが「個人のブラウザ内保存」を基本方針にしているためです。

## 11. 今後アプリを更新するには

1. `src/App.tsx` などのファイルを手元で編集する
2. GitHubのリポジトリページで、該当ファイルを開き「編集(鉛筆アイコン)」→ 内容を貼り替え →「Commit changes」
   (または、GitHub Desktopなどのアプリを使ってpushする方法もあります)
3. GitHubへの変更が反映されると、Vercelが自動的に再ビルド・再公開してくれます(数分待つだけでOKです)

## 12. 知っておいてほしい注意点

- **端末・ブラウザごとにデータが別**:iPhoneとパソコンでは別々の記録になります。同期はできません(バックアップ/復元で手動移行してください)
- **ブラウザのデータ消去ですべて消える**:定期的なバックアップを強く推奨します
- **シークレット/プライベートモードでは保存が不安定**な場合があります。通常モードでの利用を推奨します
- **写真をたくさん登録すると、ブラウザの保存容量の上限に近づくことがあります**。上限に達すると保存エラーメッセージが表示されます(データが壊れることはありません)
- 現状、ユーザーアカウントやクラウド同期はありません。必要になった場合は `src/storage/StorageAdapter.ts` を実装し直すことで対応できる設計にしてあります

## データ項目一覧(参考)

**作品記録(Piece)**
- 作品名、記録開始日
- 成形:日付、土の名前、外寸(W/D/H)、内寸(W/D/H)、写真(複数)
- 素焼き:日付、外寸(W/D/H)、内寸(W/D/H)
- 装飾:日付、技法(既定8種+カスタム追加可)、釉薬名(複数)、掛け方メモ、写真(複数)
- 本焼き:日付、窯温度、外寸(W/D/H)、内寸(W/D/H)、写真(複数)
- メモ(自由記述)

**アイディア(Idea)**
- 画像(複数)、URL、メモ、記録日

**その他**
- カスタム技法一覧(装飾タブで追加した技法名を保存)
